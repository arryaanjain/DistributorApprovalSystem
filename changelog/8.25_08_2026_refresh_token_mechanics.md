# Database-Backed Refresh Tokens & Seamless Token Rotation Plan

Fixing the authentication refresh mechanism so that users are not prematurely logged out, refresh tokens are securely persisted in PostgreSQL database instead of exposed in browser `localStorage`, and expired access tokens seamlessly refresh in the background.

## User Review Required

> [!IMPORTANT]
> **Security & Cookie Hardening**
> 1. **Database Persistence**: Refresh tokens will be stored in PostgreSQL (`refresh_tokens` table) with expiration, subject mapping, and revocation tracking.
> 2. **HttpOnly Cookie**: Refresh tokens will be delivered via `HttpOnly`, `SameSite=Lax` cookies (`Path=/api/v1/auth`) rather than exposed in client `localStorage`.
> 3. **Seamless 401 Auto-Refresh**: Frontend API client (`api.ts`) will intercept 401 Unauthorized responses, fetch a new short-lived access token using the HttpOnly refresh token, and retry the original request smoothly without forcing a user logout.
