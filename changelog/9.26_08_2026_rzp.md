# Implementation Plan - Fix & Enhance Razorpay Sample Payment Flow

Fix the sample kit payment issue in `SamplePaymentModal.tsx` and `page.tsx` so that clicking "Proceed to Razorpay Checkout" properly launches the Razorpay payment flow (or interactive test payment simulation) to complete the sample payment and activate the distributor trial.

## Proposed Changes

### Frontend Integration

#### [MODIFY] [SamplePaymentModal.tsx](file:///home/arryaanjain/Desktop/Everything/DistributorApprovalSystem/ui/components/onboarding/SamplePaymentModal.tsx)
- Transform `SamplePaymentModal` into a seamless 2-step checkout flow:
  1. **Address & Delivery Information**: Shipping address form validation.
  2. **Razorpay Payment Gateway Screen**: Interactive Razorpay payment interface presenting payment options (UPI, Credit/Debit Card, NetBanking) and Razorpay trust badges.
- Provide interactive test-mode payment selection when test keys (`rzp_test_kresconet_key`) or simulated orders are used, allowing manual testing of payment completion.
- Show clear loading, processing, and error handling states.

#### [MODIFY] [page.tsx](file:///home/arryaanjain/Desktop/Everything/DistributorApprovalSystem/ui/app/page.tsx)
- Refactor `handleCompleteRazorpayPayment`:
  - Properly load Razorpay Checkout script (`https://checkout.razorpay.com/v1/checkout.js`).
  - Validate `key_id` and `razorpay_order_id`. Omit `order_id` in Razorpay Checkout options if it is a local fallback ID, avoiding Razorpay JS SDK "Order ID does not exist" errors.
  - Correctly invoke `/onboarding/sample-payment/verify` with payment ID and signature callbacks.
  - On verification success, transition distributor application status to `trial`, set success notification, and navigate to Step 8/9.
